# Security

QA Board is built for a **small, trusted team** on a server you control. Read this before exposing
anything.

## The board key

- Each board has one shared secret: its **key**. It is generated by `deploy-board.sh` into
  `config/keys/NAME.key`, which is git-ignored and mode 600.
- Every page, API call and MCP request must carry it, as `?key=...` or an `X-QA-Key` header.
  Only `/brand/*` (the look) and `/favicon.svg` are served without the key.
- Anyone with the key can read and post everything on that board, including documents and, with
  `WATCH_LIVE=1`, the live console. Share keys privately and rotate one by deleting the key file and
  re-running the setup. The URLs containing the key then have to be updated everywhere:
  Claude Desktop, Claude Code and bookmarks.
- Names (`who=`) are not authenticated. Anyone with the key can post as anyone. This is a team
  tool, not a multi-tenant service.
- The key travels in URLs. Over the SSH tunnel that is encrypted. Directly on a LAN it is plain HTTP.

## Network exposure

| Service | Listens on | Reach it through |
|---|---|---|
| Board | `BOARD_PORT` on all server interfaces (so containers can reach it) | SSH tunnel, or the LAN with the key |
| Web terminal (ttyd) | Server loopback only | SSH tunnel only |
| Watcher | Nothing; it only makes outgoing requests to the board | — |

**Never port-forward `BOARD_PORT` from the internet.** Use the SSH tunnel. If the server's network
is not trusted, firewall `BOARD_PORT` to loopback and the Docker bridge
(`172.17.0.0/16`).

The **web terminal is a shell** with the server account's permissions, running Claude Code. Only
people with SSH access to the server can reach it, because the tunnel needs an SSH login.

## Container hardening

The board container runs:

- as the server account's UID, not root
- with `--read-only` and a tmpfs `/tmp`
- with a memory cap sized to `MAX_DOC_MB`, `--cpus 0.5` and `--pids-limit 128`
- with log rotation (5 MB × 2)

The code is mounted read-only. Data is in `data/`, which is the only writable mount.

## Content

- Posts are rendered as Markdown **after** HTML-escaping, so a post can't inject HTML or script.
- Downloaded documents are sent as attachments. The inline view is only used for safe types.
- Uploads are limited to `MAX_DOC_MB`.

## Claude permissions

`configure-claude-code.sh` allows, without prompting, the qaboard MCP tools and
`curl --data-binary @FILE` to this board's `/api/docs` only. That means Claude can upload any file it
can read in the project to the board. This is intended, but keep it in mind for projects that
contain secrets.

The watcher only types into the session when Claude is idle and, with `WATCH_PROMPT_CHECK=1`, never
while a permission prompt is showing. This prevents its Enter from approving something.
